# 평가 시연과 설명 체크리스트

## 실제 동작 시연

- [ ] Vercel 공개 URL에 접속한다. 첫 Render 접속이 늦으면 연결 안내가 보인다.
- [ ] 공개 Render `/docs`에서 스키마와 필수 endpoint를 확인한다.
- [ ] BTC 등 충분한 이력이 있는 종목에서 일봉 수집을 실행한다. Firestore `data`와 화면에서 100개 이상을 확인한다.
- [ ] 같은 종목을 다시 수집해 중복 저장 없이 기존 기록이 보존됨을 확인한다.
- [ ] 데이터 관리에서 완료된 날짜의 유효한 기록을 추가한다. Firestore 문서와 화면 목록에 반영되는지 확인한다.
- [ ] 같은 기록의 종가 또는 메모를 수정한다. 최고/최저 관계를 유지하며 요약 응답이 바뀌는지 확인한다.
- [ ] 시험용으로 추가한 기록을 삭제한다. 요약 건수가 원래대로 돌아오는지 확인한다.
- [ ] `/api/data/summary?market=KRW-BTC`에서 기간·개수·통계·지표를 확인한다.
- [ ] AI에게 ‘분석 기간과 데이터 개수, 최근 종가와 RSI를 알려줘’라고 질문한다. 요약의 숫자가 실제 답변에 반영되는지 비교한다.
- [ ] 후속 질문을 하고 Firestore `conversations`에서 사용자/AI 두 메시지가 함께 추가되는지 확인한다.
- [ ] 새 대화를 누른 뒤 대화 기록의 ‘불러오기’를 눌러 이전 메시지와 종목을 복원한다.
- [ ] 다른 종목으로 전환했을 때 데이터·요약이 섞이지 않고 새 대화가 되는지 확인한다.
- [ ] 375px 화면에서 메뉴·종목·수집·데이터 폼·채팅·불러오기를 사용할 수 있는지 확인한다. 표는 내부 가로 스크롤한다.

## 구조 설명

| 평가 질문 | 설명 근거 |
| --- | --- |
| 라우터/서비스 분리 기준 | routers는 HTTP·검증 주입, services는 계산·채팅 조합, repositories는 영속성, providers는 외부 호출 |
| `data`와 `conversations` 설계 | 조회 목적·보존 방식이 달라 분리. data ID는 market+date로 중복 방지, conversations는 UUID 문서에 최대 60개 메시지 |
| Pydantic 요청/응답 | `schemas.py`에서 실제 OHLC 관계와 범위·날짜·길이 검증. 응답 모델로 문서 내부 owner를 제외하고 Swagger 자동 생성 |
| 프론트 상태 흐름 | `app.js` state의 market·records·summary·conversationId·messages·busy. 데이터 변경 후 목록/요약 재조회, 불러오기 시 활성 ID 복원 |
| 요약→시스템 프롬프트 이유 | 데이터 전체를 넣는 대신 계산 요약을 넣어 토큰·잡음을 줄이고 데이터 기반 설명을 유도. 개별 거래/과거 지표의 모든 세부 내역은 답변할 수 없는 한계 |
| 요약 API 별도 이유 | 화면과 채팅이 같은 순수 함수를 재사용. 알고리즘 수정·단위 검증이 한곳에 모임 |
| 대화 저장 시점 | AI 성공 후 사용자·AI 한 턴을 함께 저장. 실패 시 가짜 응답이나 빈 턴을 저장하지 않음. 현재 데이터 요약을 매 질문 다시 계산 |
| 환경변수 | 키를 코드에서 분리. 로컬 `.env`, Render 서버 변수, Vercel은 공개 API 주소만. 배포가 달라도 코드 변경을 줄임 |

## 운영·확장 설명

- 콜드스타트: 초기 연결 문구·로딩, 90초 클라이언트 대기, 실패 시 새로고침 안내. 수집/질문 버튼 중복 클릭을 막는다.
- CORS: 프론트·백엔드 origin이 다르다. `ALLOWED_ORIGINS`에 실제 Vercel origin을 등록하고 methods/headers를 명시한다. CORS는 서버 API 인증의 대체물이 아니다.
- 입력 위험: 비정상 가격·날짜·긴 입력은 Pydantic으로 거부. 메모와 AI 출력은 textContent로 표시. 원시 메모는 시스템 instructions에 넣지 않음. 개인키·예외 원문을 API 응답에 노출하지 않음.
- 확장: 종목+날짜로 범위를 줄이고 페이지네이션·지표 준비 구간·요약 캐시를 도입. ‘최근 30일’ 요약을 추가할 때 services/summary.py의 대상 구간과 프론트 기준 문구를 함께 바꾸고 경계 날짜 테스트를 추가한다.
- 수치 차이: RSI Wilder 평활, EMA SMA 초기화, 볼린저 모집단 표준편차, UTC 일봉 완료 기준을 설명한다. 준비 기간 부족은 null로 남긴다.
- 비용: 모델 출력 토큰·호출 횟수·타임아웃·재시도를 제한하고 API 대시보드에서 실제 사용량을 확인한다.

## 제출 스크린샷

- [ ] 데이터 요약 + 질문/AI 실제 답변이 함께 보이는 분석 화면
- [ ] 데이터 추가 또는 수정 성공 결과와 목록이 보이는 관리 화면
- [ ] 이전 대화 불러오기 전후와 메시지가 보이는 화면
- [ ] 공개 Render Swagger 문서
- [ ] 375px 모바일 주요 기능 화면

미설정 키 안내나 통제된 테스트 응답을 실제 AI 동작 증빙으로 제출하지 않는다.
