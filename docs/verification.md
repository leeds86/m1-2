데이터 개수와 지표는 수집·수정에 따라 달라집니다.

## 수집 처리와 데이터 관리

- 일봉 재수집이 90초 대기 제한을 넘는 문제를 재현했습니다. 기존 기록마다 순차 쓰기를 시도하던 처리를, 저장된 ID를 한 번 조회해 건너뛰고 새 일봉만 최대 8개씩 동시에 저장하도록 수정했습니다.
- 중복 문서는 원자적 생성과 409 처리를 유지하여 기존 메모를 덮어쓰지 않습니다. [Firestore 클라이언트의 스레드 공유 안내](https://docs.cloud.google.com/python/docs/reference/firestore/latest/multiprocessing)를 확인했습니다.
- 수정 커밋 `54210c3`의 Render 반영 후 BTC 재수집 HTTP 200, 약 6.24초, 기존 200개 보존과 전체 204개를 확인했습니다. ETH 재수집은 HTTP 200, 약 2.31초였습니다. 시간은 해당 실행의 관측값입니다.
- 운영 화면에서 SOL 최초 수집은 새 일봉 200개 추가, 기존 0개, 기간 2026-04-11~2026-10-27로 완료됐습니다.
- 공개 데이터 API에서 별도 임시 기록으로 추가 201 → 목록 조회 200 → 수정 200 → 요약 건수 갱신 → 삭제 204를 확인했습니다. 점검 기록을 정리한 후 기존 건수가 유지됨을 확인했습니다.

## 대화와 화면

- 운영 화면에서 질문 → 실제 AI 응답 → Firestore 자동 저장을 확인했습니다.
- 브라우저 새로고침 후 대화 기록을 불러오고 후속 질문을 전송했습니다. 4개 메시지와 갱신된 기간·개수·종가·RSI 응답을 확인했습니다.
- 갱신 후 BTC 요약은 204개, 최근 종가 107,809,000원, RSI 약 39.87이며 실제 AI 응답과 일치했습니다.
- 375px 화면에서 분석·데이터 관리의 문서 가로 넘침이 없고, 데이터 입력창의 열기·취소가 동작함을 확인했습니다.
