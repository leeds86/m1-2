## 별도 코드 검토

검토자는 파일을 읽기만 했으며 다음 문제를 발견했다. 두 문제 모두 실패하는 회귀 테스트를 먼저 재현한 후 수정하고 전체 테스트를 확인했다.

1. 다른 종목 대화 불러오기 후 데이터 조회가 실패하면 이전 종목 가격이 남는 문제 → 전환 즉시 이전 요약·목록을 비우도록 수정.
2. Firestore SDK가 트랜잭션 충돌 재시도 종료를 `ValueError`로 감싸는 문제 → 원인 예외가 `Aborted`인 경우만 409 안내로 변환.

추가로 요청 후 SQLite 연결 정리와 저장 후 화면 재조회 실패 시 안내 표시를 검증·수정했다.

## 인증·저장소 연결 검증 이력

### OpenAI 키 입력 후 실제 요청 확인

- `.env`의 OpenAI 키 설정 여부와 서버 재시작 후 `ai_configured: true`를 확인했다. 키 값은 출력하지 않았다.
- 실제 웹 질문은 실패했으며, 별도 최소 길이 진단 요청에서 OpenAI가 HTTP **401 / invalid_api_key**를 반환했다.
- 접두사 형식, 앞뒤 공백·개행 여부만 확인했고 형식상 이상은 없었다. 이 결과는 `api.openai.com`에서의 인증 실패이며, Codyssey 발급 키 자체가 무효라는 증거는 아니다. 실제 AI 연결 성공으로 표시하지 않는다.
- 사용자는 OpenAI 키만 입력했다고 확인했다. 현재 Firebase 서비스 계정 환경변수는 비어 있고 저장 모드는 SQLite다.
- 이후 사용자가 Codyssey 가상 키의 안내를 제공해 아래처럼 API 주소와 호출 규격을 수정했다. 기존 키를 무조건 재발급해야 한다고 판단하지 않는다.

### GPT-6 Luna 설정 확인 (이전 시도, 현재 미사용)

- 사용자가 `.env`의 모델을 `gpt-6-luna`로 변경한 것을 확인했다.
- Luna 요청에만 `reasoning={"effort":"none"}`을 추가해 출력 1,000토큰 한도 안에서 짧은 설명을 생성하도록 맞췄다. 기존 GPT-4.1 Mini 요청에는 이 옵션을 전송하지 않는다.
- 인증 실패를 서비스 설정 문제로 구분해 HTTP 503과 `OpenAI 인증에 실패했습니다(401)` 안내를 반환한다. SDK 오류 원문이나 키 값은 노출하지 않는다.
- 변경 전 실패를 확인한 모델 옵션·인증 안내 테스트를 추가했고 전체 Python 31개, 프론트 2개 테스트가 통과했다. 서버도 새 설정으로 재시작했다.
- 과금되는 답변 생성 대신 모델 목록 GET 요청으로 인증을 확인했지만 HTTP 401 / invalid_api_key가 계속 반환됐다. 모델 변경이 반영된 사실과 키 인증 성공 여부는 별개다.

### 이전 Codyssey 안내 반영 (qacopa 도메인에서 실패한 이력)

- 사용자가 제공한 화면의 Base URL은 `https://qacopa.codyssey.kr/v1`, 경로는 `/chat/completions`다. 모델은 사용자가 선택한 `gpt-5.4-mini`를 유지한다.
- 로컬 `.env`의 비밀 키는 보존하고 `OPENAI_BASE_URL`만 추가했다. 설정 객체 → 앱 → SDK로 주소를 명시적으로 전달한다. Render 설정과 `.env.example`, README, 계정 안내에도 동일 설정을 반영했다.
- Bearer 인증, `messages`의 `role: system`, `choices[0].message.content`, 선택 `max_tokens`는 제공된 Codyssey 안내에 맞췄다. 기존 Responses 호출과 Luna 전용 옵션은 제거했다.
- 실제 SDK와 통제된 HTTP 응답으로 URL·인증·요약 주입·본문 추출을 검증한다. 빈 답변·길이 제한 답변은 실패 처리하며 인증 오류에 키/주소 일치 안내를 제공한다.
- 변경 전 `/responses` 호출·설정 누락·시스템 메시지 계약 실패를 재현한 뒤 수정했다. 최종 Python 35개, 프론트 2개 테스트가 통과했다.
- 새 백엔드로 재시작하고 브라우저에서 BTC 요약 질문을 전송했으나 **HTTP 401 인증 실패**가 표시됐다. 질문 입력은 복원됐고 가짜 답변/대화는 저장하지 않는다.
- 추가 직접 진단은 비밀 키의 Codyssey 전송에 대한 구체적 사용자 승인 부족으로 자동 보안 검토에서 차단됐다. 우회 요청은 하지 않았다. 해당 전송 승인 전에는 추가 실호출하지 않는다.
- 따라서 Codyssey 방식의 코드·설정 수정과 실제 인증 성공은 구분한다. 현재 실제 AI 생성·대화 저장/불러오기 검증은 미완료다.

### 사용자 승인 후 Codyssey 실연결 재검증

- 사용자가 `테스트 진행`으로 `.env` 키의 Codyssey 전송과 연결 테스트를 승인했다. 앞서 승인 부족으로 막힌 추가 진단을 승인된 범위에서 재개했다.
- 실제 사용 설정은 모델 `gpt-5.4-mini`, Base URL `https://qacopa.codyssey.kr/v1`이다. 요청은 `/chat/completions`로 전송했다.
- 키 출처는 로컬 `.env`였으며 파일의 값과 실행 설정이 일치했다. 프로세스 환경의 다른 키에 덮어씌워지는 문제, 앞뒤 공백, 개행은 없었다. 키 값은 출력하지 않았다.
- SDK의 Bearer 인증과 Codyssey 안내의 대체 `x-api-key` 인증을 각각 확인했으나 모두 **HTTP 401**이었다. 대체 헤더가 실제 요청에 포함된 것도 값 노출 없이 확인했다.
- 제공자가 반환한 비밀정보 없는 오류는 `authentication_failed` / `Authentication is required.`였다. 응답은 redirect가 아니었다. 키 자체의 무효·만료·권한 부족 중 어느 원인인지는 이 일반 오류만으로 구분할 수 없다.
- 인증 성공 전이므로 답변 생성·대화 자동 저장·불러오기는 여전히 실검증하지 못했다. 동일한 실패 요청을 더 반복하지 않고, 사용자가 Codyssey에서 키 활성 상태·만료·API 사용 권한을 확인하도록 안내한다.
